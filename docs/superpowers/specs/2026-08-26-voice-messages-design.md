# 她自己决定发语音消息

**Date**: 2026-08-26
**Status**: Approved, pending implementation plan
**Scope**: 飞书对话里，她可以把一条短回复作为语音条发出去；发不发由她自己决定

---

## 1. 背景

现在她只能发文字、卡片和表情包。语音条是 IM 里表达亲近的一种常见方式，
而且跟表情包一样，**发不发应该是她的表达冲动，不是调度脑的判断**——这一点
在表情包那次已经定过一次调（见 §3）。

## 2. 目标与非目标

### 目标

- 她在回复末尾写 `#语音`，系统就把这条合成语音发出去，**不发文字**
- 音色是复刻的，尽量贴人设
- 任何一步失败都退回发文字，**不丢消息**

### 非目标（本期不做）

- 他发语音给她（那是 ASR，另一件事）
- 流式 TTS（边生成边合成）
- 主动消息发语音——先在对话里验证值不值
- 语音转文字附在旁边（决定了只发语音，见 §3）

## 3. 已定的设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 谁决定发语音 | **她自己**，末尾写 `#语音` | 跟表情包同一个路子；`#表情` 实测情绪轮 25%、平淡轮 0%，她写得出来这类标记 |
| 形态 | **只发语音，不附文字** | 真人发语音就是这样 |
| 长度上限 | **20 字**（可配） | 飞书语音条没法扫一眼，长语音是骚扰；20 字正好卡在"随口一句"那个位置。超了就当没写这个标记，走文字 |
| 音色 | **复刻**，speaker_id 配置在人设 yaml | 用户决定。授权顾虑已当面提过一次 |
| 流式冲突 | **短回复延迟建卡片** | 见 §5 |

## 4. 外部依赖（已核实）

### 4.1 TTS：火山引擎大模型声音复刻

**不是 ARK。** 走 `openspeech.bytedance.com`，与 `ARK_API_KEY` 是两套服务、
两套凭证。需要在豆包语音控制台单独开通并拿到 `appid` + `access_token`。

- 合成：`POST https://openspeech.bytedance.com/api/v1/tts`
- 鉴权：`Authorization: Bearer;{token}` —— **分号，不是空格**，写错直接鉴权失败
- 复刻音色：`audio.voice_type` 填训练好的 `S_xxxx`
- 每次合成 `reqid` 必须唯一（用 UUID）
- 返回：JSON 里 base64 编码的音频，解码即二进制
- v1 接口不支持"语音合成模型 2.0"的音色；若将来换 2.0 音色需改用 v3

**声音复刻的注册流程由用户在控制台侧完成**，系统只消费拿到的 `S_xxxx`：
控制台购买/领取音色额度拿到 `S_` 开头 ID → 上传音频到
`/api/v1/mega_tts/audio/upload`（`Resource-Id: volc.megatts.voiceclone`）→
轮询 `/api/v1/mega_tts/status` 直到 `status` 为 2（训练完成）或 4（active）。

### 4.2 飞书语音消息

- 上传：`POST /open-apis/im/v1/files`，`file_type=opus`，需 **`im:resource`** 权限，
  单文件上限 30MB
- `duration`（毫秒）应显式传，不传时飞书自行解析 opus 头，头信息不完整会显示 0
- 发送：`msg_type=audio`，`content` 为 JSON 字符串 `{"file_key": "..."}`
- 形状与现有 `_send_image`（上传拿 key → 发消息）完全一致

### 4.3 ffmpeg

TTS 返回的音频格式由请求参数决定（默认 mp3），飞书要 opus。本机 ffmpeg 8.1.2 已装、`libopus` 编码器可用。

```
ffmpeg -i in.mp3 -acodec libopus -ac 1 -ar 16000 out.opus
```

**ffmpeg 是新引入的外部二进制依赖**，缺失时降级发文字（§7），并在启动时打一行提示。

## 5. 流式冲突与解法

现在的顺序是：建流式卡片 → 发给对话 → 把生成的字往卡片里推。
而 `#语音` 标记在**生成结束时**才出现——那时文字已经在屏幕上了。
"只发语音"和"句尾决定"直接冲突。

**解法：短回复延迟建卡片。** 先缓冲，直到

- 累计 **≥40 字**，或
- 生成结束

才建卡片。这个阈值**必须大于 `max_chars`**，否则一条够格发语音的回复会在
生成结束前就把卡片建出来，"卡片从来没出现过"就不成立了。40 对 20 留了一倍余量。

于是：

| 情况 | 行为 |
|---|---|
| 结束时 ≤20 字且带 `#语音` | 合成语音发出，**卡片从来没出现过** |
| 结束时 >20 字但带 `#语音` | 标记忽略，正常发文字（§3 的长度上限） |
| 其他 | 建卡片，把缓冲内容一次刷进去，之后照常流式 |

代价：短回复的卡片晚出现约 0.5–1.5 秒。这恰好是"卡片立刻出现"最不重要的情况——
一条二十字的回复本来就是一瞬间的事。长回复的流式体验不变。

考虑过并否决的两个替代：让 orchestrator 提前决定（把决定权从她手里拿走，
与 §3 第一条相悖）；改成行首标记（未经测试，而且与"先写你要发出去的那条消息"
那条格式指令打架）。

## 6. 架构

```
src/lingxi/voice/
├── tts.py        # 火山 TTS 客户端：文本 + speaker_id → 音频字节
└── encode.py     # ffmpeg mp3 → opus 单声道 16k，返回 (bytes, duration_ms)
```

改动的既有文件：

| 文件 | 改动 |
|---|---|
| `conversation/output_schema.py` | 解析 `#语音` 标记 |
| `channels/feishu.py` | 新增 `_send_audio`；流式路径改为延迟建卡片 |
| `persona/models.py` | 新增 `VoiceConfig` |
| `config/personas/tangkeke.yaml` | `voice:` 块 |

`#语音` 是**没有值的裸标记**，而 `_STICKER_TAG` 的正则要求 `#表情` 后面跟一个
情绪词，所以它需要自己的模式，不能直接套用那一条——沿用的是"独占一行、
从对白里摘掉、句尾出现"这套做法，不是同一个正则。

### 6.1 人设配置

```yaml
voice:
  enabled: true
  provider: "volc"
  speaker_id: "S_xxxxxxxx"   # 控制台复刻完成后填
  max_chars: 20              # 超过就走文字
```

`enabled: false` 或 `speaker_id` 为空 → 标记被忽略，永远走文字。
这也是没有凭证时的默认状态。

### 6.2 一条语音消息的路径

```
responder 输出 "……#语音"
  → parse_turn_output 摘出标记，speech 里不留痕迹
  → 长度 ≤ max_chars？
      否 → 当作普通文字回复
      是 → TTS 合成 → ffmpeg 转 opus → 上传拿 file_key → msg_type=audio 发出
```

## 7. 失败处理

**任何一步失败都退回发文字**，跟表情包同一个原则：一个附加功能的问题
永远不该让这一轮消息丢掉。

| 失败点 | 行为 |
|---|---|
| `voice.enabled` 为假 / 无 speaker_id | 忽略标记，发文字 |
| 超过 max_chars | 忽略标记，发文字 |
| TTS 报错 / 超时 | 记一行日志，发文字 |
| ffmpeg 缺失或转码失败 | 记一行日志，发文字 |
| 上传或发送失败 | 记一行日志，发文字 |

文字兜底走的是已经存在的静态卡片路径，与卡片创建失败时的兜底相同。

## 8. 测试策略

离线、不联网、不花钱：

- `#语音` 标记解析：摘出、不残留进对白、全角冒号与空格容错、行中间的 `#语音` 不算
- 超长时标记被忽略（边界：正好 20 字发语音，21 字走文字）
- `voice.enabled=false` / 空 speaker_id 时标记被忽略
- ffmpeg 编码：产出真的是 opus，`duration_ms` 与输入时长相符（需要本机 ffmpeg）
- TTS 客户端：假 HTTP，断言 `Bearer;` 分号格式、`reqid` 每次不同、base64 正确解码
- 延迟建卡片：短回复（<40 字且带标记）不建卡；长回复建卡且缓冲内容不丢
- 每个失败点都退回文字，且原文一个字不少

**验收标准**：跑一条真实的语音消息到飞书，确认气泡显示时长而不是 0。
这一步需要凭证，由用户配好后手动验一次。

## 9. 需要用户完成的前置

1. 飞书后台开 **`im:resource`** 权限
2. 豆包语音控制台开通声音复刻，拿到 `appid` + `access_token`，完成音色注册，
   拿到 `S_xxxx`
3. `.env` 填 `VOLC_TTS_APPID` / `VOLC_TTS_TOKEN`；人设 yaml 填 `speaker_id`

在这三项完成之前，功能处于"标记被忽略、一切照旧"的状态，**不影响现有对话**。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 她根本不写 `#语音` | `#表情` 的实测数据支持她写得出这类标记，但语音的频率未知。实现后按表情包那次的做法实测一轮 |
| 延迟建卡片让短回复显得迟钝 | 阈值（40 字）可配；实测体感后调 |
| TTS 首包延迟叠加在回复之后 | 只有 ≤20 字的短句走语音，合成时间短。若实测过慢，考虑 WebSocket 长连接（本期不做） |
| ffmpeg 不在部署环境 | 启动时检测并打提示；缺失即降级发文字，不影响对话 |
| 复刻音色的授权 | 已向用户明示，由用户决定并承担 |
